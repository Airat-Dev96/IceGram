# Проверки перед выпуском icegram

Пока сборка и runtime-проверки не выполнены, нельзя считать APK готовым.

## Автоматические

- `sh Tools/icegram/test-policy.sh`: расчёт лимитов для классов памяти
  от 16 до 4096 МиБ, исходные лимиты при отключении компактного режима,
  крайние значения, суммарный потолок 20 МиБ в компактном режиме.
- `python3 Tools/icegram/check-source.py`: XML, русские/английские строки,
  имя пакета, launcher alias, отсутствие чужого Firebase config,
  использование policy в ImageLoader, сохранение full/плагинов и отключение карт.
- `python3 Tools/icegram/test-apk.py`: тесты проверки содержимого APK на
  искусственных архивах. Это не сборка или проверка настоящего APK.
- `bash gradlew :buildSrc:testWalletCallbacks`: на официальном Wallet 19.2.1
  проверяет удаление только старых Binder-транзакций 1/2, неизменность всех
  остальных 17 веток (включая isReadyToPay/PaymentData), JVM-стеки и отказ при
  неожиданном изменении SDK. Это не runtime-проверка Google Pay.
- JDK 17, Python 3.11 и toolchain из `ICEGRAM.md`, затем
  `bash gradlew :TMessagesProj:generateAppIcons :TMessagesProj:assembleFullArm64Debug`:
  Java/Kotlin, ресурсы, manifest merge, JNI и Python SDK плагинов.
  Затем обязательно `assembleFullArm64Release` с R8 и тем же шагом генерации.
- После сборки CI запускает `python3 Tools/icegram/verify-apk.py --abi arm64`:
  проверяет настоящую APK-подпись через `apksigner`, совпадение сертификата с
  постоянным ключом, пакет, имя, launcher alias, единственную ABI, ELF-заголовки,
  библиотеки Python/hooking и Python 3.11 bytecode SDK. Проверяет отсутствие
  Maps metadata и исходных Maps class descriptors; одна эта проверка DEX
  не исключает обфусцированные классы и не заменяет проверку зависимостей.
   У Wallet 19.2.1 есть неиспользуемый API карт лояльности со ссылкой на
   Maps `LatLng`: buildSrc до R8 удаляет только legacy Binder callbacks
   MaskedWallet/FullWallet, которые приложение не использует. SHA-256
   канонического диспетчера закреплён; смена SDK требует повторной проверки.
   Современные PaymentsClient callbacks, Firebase PNV и Cast не отключаются.
   ASM остаётся только инструментом сборки, в APK не добавляется.
   R8 подавляет только отсутствующий `LatLng` и через
  `-checkdiscard` требует удаления всех девяти ссылающихся на него классов
  Wallet. Возврат `LatLng` в DEX также отклоняется проверкой APK.
  В artifact сохраняется `ICEGRAM_APK_VERIFICATION.json` с SHA-256 и явной
  отметкой, что runtime-тесты ещё не выполнены. Значения API/подписи не выводятся.
  Локально можно передать `--apk`, `--build-tools` и публичный DER-сертификат
  через `--certificate`, не передавая пароли в командной строке.

### Диагностика R8 без полной сборки

В workflow `Build icegram APK` параметр `r8_diagnostics_only=true` только
выгружает координаты внешних зависимостей и их consumer rules. Этот запуск
не создаёт APK, и его успешный статус не означает успешную сборку приложения.
Отчёт `icegram-r8-rules-*` также сохраняется после обычной сборки/ошибки R8.
Исходные JAR/AAR, `BuildConfig`, API/Firebase-конфигурация и ключ подписи
в диагностический artifact не включаются.

## На устройстве

1. Чистая установка отдельно от официального Telegram и exteraGram.
   Значок и название icegram. Нет предложения обновиться APK от exteraGram.
2. Вход со своими API/Firebase-настройками. Текст, файлы, фото, голосовые,
   отправка/получение сообщений и восстановление соединения.
3. Входящий звонок и push при свёрнутом приложении, заблокированном экране,
   после переключения Wi-Fi/LTE. Проверить ограничения батареи Android.
4. На новой установке GIF/видео не запускаются автоматически.
   Ручное воспроизведение работает. Включение эффектов в детальных настройках
   сохраняется после перезапуска и получения настроек сервера Telegram.
5. «Применить Ice Mode» выключает эффекты, включая уже активное размытие;
   изображение не остаётся устаревшим. Возврат эффектов работает.
6. Компактный кэш: прокрутка чатов с фото, открытие полноэкранных фото,
   анимированные стикеры/эмодзи, обои. Нет recycled-bitmap crashes.
   Отключение переключателя и перезапуск возвращают upstream-лимиты.
7. Не появляются лишний процесс HTML-виджетов и его прогрев на старте.
   Виджет по нажатию запускается; включение прогрева + перезапуск работает.
8. Скрытие телефона не меняет серверную приватность. Кнопка сохранения
   в меню отправляет в «Избранное» только по нажатию пользователя.
9. Русский/английский интерфейс, светлая/тёмная тема, крупный шрифт,
   экранный диктор, поворот экрана и планшетная компоновка.
10. В настройках рядом с названием/версией есть атрибуция exteraGram
    с открывающейся ссылкой на исходный проект.
11. Пункт плагинов доступен. Проверить доверенный тестовый плагин:
    загрузку Python SDK, включение/выключение и hooking после перезапуска.
    Не ставить плагины с доступом к реальным сообщениям ради теста.
12. Геосообщения, места в профиле/канале, бизнес-адреса и места в историях
    не открывают встроенную карту и не приводят к падению. Нажатие на выбор
    места сообщает, что карты отключены. Сетевая проверка: миниатюры карт
    не запрашиваются; внешний браузер/приложение карт проверять отдельно.
13. Проверить собранный APK через APK Analyzer: нет Google Maps SDK,
    присутствуют Python и hook-библиотеки для выбранной ABI. Проверить merged
    manifest и запуск в светлой/тёмной теме на Android до 12 и 12+:
    заставка, launcher alias и стартовый экран показывают значок icegram.

## Сравнить с upstream full

Использовать release обеих версий, одну архитектуру, один телефон и один
набор чатов/медиа, одинаковые плагины (для базового замера — ни одного).
Не сравнивать full-debug с lite-release.

- Замерить холодный запуск 10 раз (`adb shell am start -W`), сравнить медиану.
- Снять `adb shell dumpsys meminfo org.icegram.messenger` после одинакового
  сценария прокрутки и 30 секунд простоя; это PSS всего процесса, не сумма LRU.
- Проверить кадры через `adb shell dumpsys gfxinfo org.icegram.messenger`.
- Размер APK сравнивать для одной ABI, одинаковой подписи/типа сборки.
- Батарею и сетевой трафик оценивать длительным одинаковым сценарием,
  а не мгновенным показателем системного монитора.
- Повторить с выключенным компактным кэшем: если повторное декодирование
  ухудшает плавность/нагрев, предпочесть исходный кэш на этом устройстве.

Записать модель телефона, Android, версии клиентов и параметры сборки.
Не публиковать логи, содержащие номера телефонов, токены и сообщения.
